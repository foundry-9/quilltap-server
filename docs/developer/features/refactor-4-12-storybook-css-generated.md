# Refactor 4.12 — The theme-storybook mirror is generated, not hand-written

**Status:** Phases 1 and 2 implemented (2026-11-02); Phase 3 not started. Decisions taken: the package publishes at release (a `publish-theme-storybook` job in `release.yml`), and storybook-only rules are dropped. Report: [refactor-4-12/storybook-css-diff.md](refactor-4-12/storybook-css-diff.md). Originally proposed 2026-11-02. Part of the [4.12 refactor set](refactor-4-12.md). Touches `packages/theme-storybook`, so the publish rule in CLAUDE.md applies to the first shipping change.

## 1. The problem

`packages/theme-storybook/src/css/qt-components.css` is a hand-maintained, de-Tailwinded copy of `app/styles/qt-components/*.css`. CLAUDE.md makes the copy mandatory on every `qt-*` change ("Mirroring `qt-*` into theme-storybook is not optional … port the whole family … bump the package's patch version and stop and ask the human to `npm publish`").

The 4.12-dev cycle shows what that costs and how well it works.

| Measure (2026-11-02, `HEAD` = 94f04176) | Value |
|---|---|
| App source, `app/styles/qt-components/*.css` | 12,439 lines, 894 distinct `.qt-*` selectors |
| Mirror, `packages/theme-storybook/src/css/qt-components.css` | 7,436 lines, 567 distinct `.qt-*` selectors |
| App selectors missing from the mirror | **334** (37 %) |
| Mirror selectors that no longer exist in the app | 7 (`qt-dialog-backdrop`, `qt-hamburger`, `qt-left-sidebar-header`, `qt-left-sidebar-mobile-open`, `qt-left-sidebar-overlay`, `qt-left-sidebar-overlay-visible`, `qt-tab-content`) |
| `@apply` occurrences in the app source that a human translated by hand | 783 |
| Commits in 4.12-dev that touched the mirror | 6 (29ba4d3f, 3c41cf3d, db6190b4, df8d4d70, 87c3860d, 94f04176) |
| theme-storybook patch versions published in 4.12-dev for mirror reasons | 1.0.92 → 1.0.98 (8 `package.json` bumps) |

Two of those commits (87c3860d, 94f04176) were themselves repairs of drift: the "undefined CSS custom properties" fix found the mirror reading `--qt-text-primary` and friends that the app never defined, and the WCAG pass had to port the alert, footer, settings-shell and settings-background families because they had never been mirrored. The mirror also differs from the app in ways nobody chose: Tailwind v4 compiles `hover:` into `@media (hover: hover) { … :hover }`, and the hand copy writes a bare `:hover`, so a theme author testing on a touch device sees different hover behaviour in the storybook than in Quilltap.

The process is the cost, not any one change: every `qt-*` edit is written twice, reviewed twice, and gated on an `npm publish` before it can be committed.

## 2. Goal

One source. `app/styles/qt-components/` is the only place a `qt-*` rule is written. The storybook's file is build output, byte-stable, regenerated by a script and checked by the lint gate, so the mirror can never be stale or partial again. The CLAUDE.md rule shrinks from "mirror faithfully, by hand, the whole family" to "run the generator".

## 3. Non-goals

- Changing any `qt-*` rule's behaviour in the app. The generated file reproduces what the app compiles today, including the `@media (hover: hover)` wrapping the hand copy left out.
- Changing how a theme author consumes the package (`@quilltap/theme-storybook/css/qt-components.css` stays an export at the same path).
- Removing the `npm publish` step. Whether it stays per-change or moves to per-release is a decision for the human (§8).
- Touching `create-quilltap-theme`, the stylebook or the bundled themes, beyond noting in §8 that the same generator could feed them later.

## 4. Known state (verified 2026-11-02)

- **App side.** `app/globals.css:1` imports Tailwind (`@import "tailwindcss"`), defines the token map at `:220-271` as `@theme inline { --color-background: var(--theme-background); … }`, and imports the component layer at `:288` (`@import "./styles/qt-components/_index.css"`). `_index.css` imports `_variables.css` first, then the family files, each wrapped in `@layer components { … }` (e.g. `_surfaces.css:10`). The families use `@apply` freely (`_chat.css` 269 times, `_layout.css` 165, `_content.css` 153, `_surfaces.css` 142) and reference the token names (`bg-accent`, `text-muted-foreground`, `rounded`, `transition-colors`).
- **`_icons.css` is already generated.** `scripts/generate-icon-css.ts` writes it from the icon registry, the output is committed, and `npm run generate:icon-css` is the refresh command (`package.json:31`). That is the precedent this spec follows.
- **Storybook side.** `packages/theme-storybook/src/css/qt-components.css` is imported by `src/preview.tsx:15` and exported raw from `src/css/` by `package.json` (`"./css/qt-components.css": "./src/css/qt-components.css"`). `quilltap-defaults.css` (200 lines) defines both the `--theme-*` tokens (97 declarations) and the `--color-*` aliases (49), so either spelling resolves in the storybook. The mirror file contains one `@layer` and no `@apply`.
- **Stories.** `src/stories/components/*.tsx` reference `qt-*` classes by name. One of the seven orphan classes, `qt-tab-content`, is used by `Tabs.tsx:43,51,59`; the other six are referenced by nothing.
- **Lint gates.** `npm run lint` runs ESLint, the spelling sweep, `scripts/check-qt-classes.mjs` and `scripts/check-css-vars.mjs` (`package.json:34`). Neither checks the mirror.
- **Build tooling.** The root depends on `tailwindcss ^4.2.2` and `@tailwindcss/postcss ^4.3.3` (`package.json:122,149`), which brings `@tailwindcss/node` with the `compile(css, { base, onDependency })` API. The package itself builds with `tsup` (`packages/theme-storybook/package.json` `scripts.build`) and does not process CSS.

## 5. Design

### 5.1 The generator

`scripts/generate-storybook-css.mjs`, run as `npm run generate:storybook-css`.

1. **Assemble a virtual entry.** Not the app's `globals.css` (that would emit preflight and every utility the app uses). The entry is:

   ```css
   @reference "tailwindcss";
   @theme inline { …the block copied verbatim from app/globals.css… }
   @import "./app/styles/qt-components/_index.css";
   ```

   `@reference` loads Tailwind's theme and utilities for `@apply` resolution without emitting them. The `@theme inline` block makes `bg-accent` compile to `background-color: var(--theme-accent)`, exactly as it does in the app. To keep that block from becoming a second copy, move it out of `globals.css` into `app/styles/theme-tokens.css` and `@import` it from both `globals.css` and the generator's entry. That is the one app-side edit.

2. **Compile** with `@tailwindcss/node`'s `compile`, `base` set to the repo root so `@import` paths resolve, then `build([])` with no candidates (nothing but `@apply` needs expanding). The result is plain CSS with every `@apply` expanded.

3. **Post-process**, minimal and mechanical:
   - Prepend a header: generated file, do not edit, source path, regeneration command.
   - Keep the `@layer components { … }` wrappers. The app's rules live in that layer, unlayered theme CSS beats them, and the storybook's own theme CSS is unlayered too, so keeping the layer is the faithful choice. (Tailwind emits no `@layer theme, base, components, utilities;` statement under `@reference`; add it to the header so the layer order is explicit.)
   - Strip comments that are only `@apply` provenance, if Tailwind leaves any. Keep the family banner comments; they are what makes the file readable to a theme author.
   - Run the output through the same `autoprefixer` the app's PostCSS uses, so vendor prefixes match.

4. **Write** `packages/theme-storybook/src/css/qt-components.css`. The output must be deterministic: same input, same bytes, on every platform. (Sort nothing; Tailwind's output order follows source order.)

### 5.2 The gate

`scripts/check-storybook-css.mjs`, added to `npm run lint` after `check-css-vars.mjs`: regenerate to a temp buffer and compare to the committed file. A difference fails lint with "run `npm run generate:storybook-css`". This is the same shape as the stale-trigger check in `ensureChatMessageFtsSchema`: the artefact cannot silently drift.

A unit test (`__tests__/unit/scripts/generate-storybook-css.test.ts`) compiles a three-rule fixture and asserts the expanded output, including the `@media (hover: hover)` wrap, so a Tailwind upgrade that changes the compiler's output shape is caught as a test failure, not as a storybook that looks different.

### 5.3 What happens to the hand copy

It is deleted and replaced by the first generated output. Expected consequences, each verified in Phase 2:

- The 334 missing families appear. The storybook gets, for the first time, the full component surface.
- The six unused orphan classes vanish. `qt-tab-content` also vanishes; `Tabs.tsx` is changed to use whatever the app's tab stories actually use (`qt-tab-panel` or the current equivalent, confirmed by reading `components/ui/tabs` at implementation time).
- Hover rules gain `@media (hover: hover)`. This is a fidelity improvement, not a regression.
- Hand-written storybook-only variations (any rule in the mirror that was never in the app) disappear. Phase 1's diff report lists them so the human can decide whether any was a storybook feature worth porting *into the app*.

### 5.4 CLAUDE.md

The "Mirroring `qt-*` into theme-storybook is not optional" paragraph becomes:

> **`packages/theme-storybook/src/css/qt-components.css` is generated.** Never edit it. After any change under `app/styles/qt-components/` run `npm run generate:storybook-css` (lint fails if you forget), bump the package's patch version, and [publish rule as decided in §8].

The "port the whole family" and "mirror faithfully, including quirks" sentences go, because the generator does both by construction.

## 6. Phases

**Phase 1 — Generator and report (no package change).** Write the generator and the gate. Run the generator to a scratch path, not the package. Produce `docs/developer/features/refactor-4-12/storybook-css-diff.md`: a selector-level diff between the generated output and the hand copy (missing, orphaned, differing declarations). Hand the report to the human. Nothing published.

**Phase 2 — Cutover.** Move the `@theme inline` block to `app/styles/theme-tokens.css`. Replace the mirror with the generated file. Fix `Tabs.tsx`. Add the gate to `npm run lint`. Bump theme-storybook's patch version; the human publishes; commit. Update CLAUDE.md, `packages/theme-storybook/README.md` (the file is generated; what it contains) and `docs/developer/THEMING.md` or wherever the mirror rule is repeated (grep `qt-components.css` in `docs/`).

**Phase 3 — Reuse (optional, separate decision).** The same compile step can feed `create-quilltap-theme`'s scaffolded preview and the bundled themes' Storybook preview, if they carry copies today. Out of scope until Phase 2 has shipped.

## 7. Tests and verification

- Unit: the fixture test in §5.2.
- Lint: the gate in §5.2, run in CI with the rest of `npm run lint`.
- Manual (Phase 2): `npm run build` in the package, open the storybook against two bundled themes (Art Deco dark, Earl Grey light) and the default, and walk the stories that gained families (alerts, footer, settings shell, Document Mode, help dialog). Screenshots in the PR.
- Regression: `npm run lint` and the full unit suite unchanged in the app; the app's own CSS is not touched except the token-block move, and `check-css-vars.mjs` continues to pass.

## 8. Decisions needed from the human

1. **Publish cadence.** With staleness mechanically detectable, the per-change `npm publish` could become per-release (as `packages/quilltap` already is). Recommendation: per-release, with the version bump still per change so consumers see every change in the published CHANGELOG. If the per-change publish stays, nothing in this spec changes except the sentence in CLAUDE.md.
2. **Storybook-only rules.** Phase 1's report may show rules a theme author relies on that the app never had. Keep (port into the app), or drop. Default: drop.

## 9. Risks

- **Tailwind compile API stability.** `@tailwindcss/node`'s `compile` is what `@tailwindcss/postcss` itself uses, but it is not a documented public contract. The fixture test is the tripwire; the fallback is running the entry through PostCSS with `@tailwindcss/postcss`, which is documented.
- **Output churn on Tailwind upgrades.** A minor Tailwind bump may reorder or reword declarations and produce a large mirror diff. That is noise, not drift, and the gate makes the regeneration a one-command step in the upgrade commit.
- **Package consumers who read the file as documentation.** The generated file is less commented than the hand copy. The family banners survive (they are in the app source), and the README gains a "where the rules come from" section.

## 10. As built (2026-11-02)

- **Generator:** `scripts/lib/storybook-css.mjs` (shared core), `scripts/generate-storybook-css.mjs` (`npm run generate:storybook-css`, `--out` for a scratch path), `scripts/check-storybook-css.mjs` (fifth `npm run lint` gate). The token map and the class-based `dark` variant moved to `app/styles/theme-tokens.css`; the app's compiled CSS is byte-identical before and after the move.
- **Comments.** Tailwind drops ordinary comments, hoists every `/*! */` comment to the top of the output, drops unknown at-rules and merges same-named `@layer` blocks, so §5.1's "keep the family banners" could not be had by a header pass. The generator inlines each family (in `_index.css` order) instead of `@import`ing `_index.css`, turns every statement-level comment (top level, or directly inside a top-level `@layer`) into a marker rule that compiles through untouched, and swaps the markers back into the original comments after autoprefixing. Comments inside rule bodies are dropped. With the comments stripped, the output is identical to a plain `@import "_index.css"` compile.
- **Tailwind license banner** is kept (it ships Tailwind-generated `@property` and `@layer properties` blocks). The layer-order statement is `@layer properties, theme, base, components, utilities;`, the order the app gets.
- **Test:** `__tests__/unit/scripts/generate-storybook-css.test.ts`. `@tailwindcss/node` registers module hooks, which Jest's sandbox refuses, so the compile half runs the real module in a child `node` process; the comment marking is tested in-process.
- **Decorator.** The default theme rendered without `data-theme`, and the app's `--qt-*` defaults sit on `[data-theme]`, so `ThemeDecorator` now always sets it (plus a `light`/`dark` class and `data-color-mode`), matching `applyThemeToDom`.
- **Tabs story** follows `EntityTabs`: `qt-tab-divider` under the group, unstyled panel.
