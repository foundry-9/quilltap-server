# Dynamic backgrounds

Status: **implemented** in 4.14-dev (2026-11-17). Written 2026-11-17.

**As built** — deviations from the text below, all small:

- `loadCollagePool` takes `{ scope, id, userId }` (projects carry no `userId`, so the request's user scopes `findByProjectId`).
- The visible-tab gate uses the existing `useWorkspaceTabVisible()` rather than `useWorkspaceTabId` + `useWorkspace`.
- Image-tool pictures share the Lantern Backgrounds mount (under `tool/`), so the pool resolves Lantern link paths (one `findByMountPointId` read) rather than trusting the mount id alone.
- Pictures without a moderation record are dated "before 4.14" (the column shipped in 4.14, not 4.13).
- The orchestration (`describeCollage`, `drawCollage`, the 8-entry cache) lives in `lib/dynamic-backgrounds/index.ts`; the route only parses and serves.
- `.qtap` exports do not carry chat settings, so the export schema is unchanged; backups carry the whole row.

## 1. What it is

An instance-wide Appearance setting, independent of the active theme. When on,
three pages paint a **collage** of generated pictures as their background
instead of their usual one, and pick a fresh random collage every few minutes:

| Page | Route | Pool | Layout |
|---|---|---|---|
| Home | workspace `home` tab | every story background on the instance | rows |
| Project | `/prospero/[id]` | story backgrounds generated by that project's chats | rows |
| Character | `/aurora/[id]` | avatars generated for that character (avatar rolls) | columns |

The collage is tiled edge to edge with no gaps. Pictures keep roughly their own
shape, so tiles differ in width (rows) or height (columns), but every row has
the same height and every column the same width.

### Decisions already made (do not reopen)

1. **Server-composed.** The server composes one WebP with `sharp`; the client
   receives a single URL and feeds it to the existing single-URL background
   plumbing (`--story-background-url`, `useReportWorkspaceBackdrop`). No DOM
   tiling, no change to the workspace backdrop registry.
2. **Unknown moderation is a best-effort guess.** `files.generationModeration`
   was not backfilled, so older pictures are `null`. With uncensored pictures
   disallowed, a `null` picture is shown unless a chat it is linked to is
   currently Unmoderated or was flagged by the danger classifier (§5).
3. **The collage wins on a project page.** With the setting on and enough
   pictures, a project shows the collage whatever its own
   `backgroundDisplayMode` says. The project mode applies only when the
   setting is off or the pool is below the floor.
4. **Repeat, with a floor.** A pool of 3 or more distinct pictures is repeated
   to fill the grid (never the same picture twice in a row). Fewer than 3 →
   no collage; the page shows whatever it shows today.

## 3. Server

New module `lib/dynamic-backgrounds/`. Everything about pools, eligibility,
layout and composition lives here; routes and hooks are thin callers.

```
lib/dynamic-backgrounds/
  settings.ts      resolveDynamicBackgroundSettings(repos) — the one reader
  pools.ts         loadCollagePool(scope, id, repos) → CollageSource[]
  eligibility.ts   filterForCollage(files, settings, repos) — §5
  layout.ts        planCollage(...) — pure, no I/O, no sharp — §4
  compose.ts       composeCollage(plan, sources) → Buffer (WebP) — sharp
  seed.ts          mulberry32 + string→seed hash (pure)
  index.ts         public surface
```

### 3.1 Pools (`pools.ts`)

```ts
type CollageScope = 'home' | 'project' | 'character';
interface CollageSource {
  fileId: string; sha256: string;
  width: number; height: number;   // see "missing dimensions"
  file: FileEntry;                 // for fileStorageManager.downloadFile
}
```

**What is a story background.** `lib/photos/chat-gallery.ts` already has
`isStoryBackgroundFile(file, paths)`: `folderPath === '/story-backgrounds/'`,
or a mount link under `generated/`. Move that predicate (and `isAvatarFile`
only if needed) to a shared module, e.g. `lib/photos/generated-image-kind.ts`,
and have `chat-gallery.ts` import it — one definition, not two. For the
project-less case the handler writes into the Lantern Backgrounds mount
(`getLanternBackgroundsStore`, subfolder `generated`); the cheap test is
`parseMountBlobStorageKey(file.storageKey)?.mountPointId === lantern.mountPointId`.
Verify nothing else is written into that mount under another subfolder before
relying on the mount id alone; if something is, resolve link paths as the
gallery does.

- **home** — every `files` row that is a story background. Add one repository
  finder (`FilesRepository.findGeneratedImages()`: `source = 'GENERATED'`,
  `category = 'IMAGE'`, `generationKey IS NULL`) and classify in JS. Do not
  walk chats one by one.
- **project** — story backgrounds whose `projectId` is the project **or**
  whose `linkedTo` names a chat currently in the project (a chat can be moved
  into a project after its backdrops were painted). Chats via the repository,
  files via `findByLinkedToAny(chatIds)` plus `findByProjectId`. 404 on an
  unknown project.
- **character** — avatar rolls: export `findRollsForCharacter` from
  `lib/photos/avatar-rolls-service.ts` and call it (a roll is a `files` row
  with a non-null `generationKey` tagged with the character). Read the
  character with `findByIdRaw`; an archived or missing character has no pool.

All pools: image mime types only, deduplicated by `sha256`, then passed through
`filterForCollage`.

**Missing dimensions.** Rows with null `width`/`height` are kept and assumed
16:9 (story backgrounds) or 2:3 (avatars). Tiles are cover-cropped, so a wrong
guess costs a little cropping, never distortion.

**Floor.** `MIN_COLLAGE_POOL = 3` distinct pictures after filtering. Below it
the scope is *unavailable*.

### 3.2 API

One route, `app/api/v1/system/dynamic-backgrounds/route.ts`, `GET` only, with
`withCollectionActionDispatch`:

**`GET /api/v1/system/dynamic-backgrounds?scope=…&id=…&orientation=…`**
(default, JSON). Query parsed by a strict Zod schema: `scope` enum; `id` a
UUID, required for `project` / `character` and refused for `home`;
`orientation` `landscape` (default) | `portrait`.

```jsonc
{ "enabled": true, "available": true, "count": 41,
  "refreshMinutes": 3,
  "url": "/api/v1/system/dynamic-backgrounds?action=image&scope=home&orientation=landscape&seed=9f3a1c…" }
```

`url` is null when the setting is off or the pool is below the floor. The
server mints a fresh random `seed` (hex) on every call — that is what makes
each refresh a new collage.

**`GET …?action=image&scope=…&id=…&orientation=…&seed=…`** → `image/webp`.

- Re-resolves settings and re-runs the pool and filter **itself**. The
  uncensored decision is never a query parameter.
- 404 when the setting is off, the scope is unknown or the pool is below the
  floor.
- Deterministic for a given (scope, id, orientation, seed, pool): the pool is
  sorted by `fileId` before the seeded shuffle.
- Served through `serveStoredBytes` (`lib/api/serve-stored-bytes.ts`) as an
  inline raster image — these are user bytes. Add
  `api/v1/system/dynamic-backgrounds` to the CSP-exempt `source` pattern in
  `next.config.js` so the route's own policy survives (the "new byte route
  joins both" rule), and extend whatever grep-test holds that list.
- A small in-process cache of composed buffers (last 8, keyed by the full
  query string plus a pool fingerprint), held with `processSingleton` (bug
  235), so a re-request of the same URL — a second pane, a reload — does not
  recompose.

Debug logs on both paths (scope, pool size before/after filtering, tile count,
compose milliseconds); `warn` when a tile's bytes cannot be read.

Add the route to `docs/developer/API.md`.

## 4. Layout and composition

### 4.1 Canvas

| orientation | canvas |
|---|---|
| landscape | 1920 × 1080 |
| portrait | 1080 × 1920 |

The page paints it with `background-size: cover`, so a viewport of another
shape crops the outer edge of the outer tiles. That is accepted.

### 4.2 `planCollage` (pure)

```ts
planCollage(input: {
  mode: 'rows' | 'columns';
  canvas: { width: number; height: number };
  sources: Array<{ key: string; aspect: number }>;  // aspect = w / h
  random: () => number;                             // seeded
}): Array<{ key: string; x: number; y: number; width: number; height: number }>
```

Constants live at the top of `layout.ts`:

| | landscape | portrait |
|---|---|---|
| rows (home, project) | 3–5 | 4–6 |
| columns (character) | 3–7 | 2–4 |

Aspect is clamped to `[0.5, 2.4]` before planning so one panorama or one sliver
cannot swallow a band.

**Rows.** Pick the row count uniformly from the range. Row height =
`canvas.height / rows` (integer; the last row absorbs the remainder). For each
row, draw pictures and append tiles of natural width `rowHeight × aspect` until
the running width ≥ `canvas.width`. Then scale every tile width in that row by
`canvas.width / runningWidth` and round so they sum exactly to `canvas.width`
(the last tile absorbs the remainder). If dropping the final tile leaves the
row closer to the target width than keeping it (and at least one tile
remains), drop it first — this keeps the scale factor near 1.

**Columns.** The same algorithm turned ninety degrees: equal column width
`canvas.width / columns`; tiles of natural height `columnWidth / aspect`
stacked until ≥ `canvas.height`, then heights scaled to sum exactly.

**Drawing pictures.** Shuffle the pool (Fisher–Yates on `random`) into a deck
and deal from it; when the deck runs out, reshuffle. Never place a picture
directly after itself in the same band: if the next card equals the previous
tile, swap it with the following card (a pool of ≥ 3 always has one).

**Invariants (tested):** tiles are integer rectangles; they cover the canvas
exactly with no overlap and no gap; band sizes are equal to within the
rounding remainder; band count is inside the range; no band holds the same
picture in adjacent tiles; same seed + same sources → same plan.

### 4.3 `composeCollage`

For each tile: `fileStorageManager.downloadFile(file)` →
`sharp(bytes).rotate().resize(width, height, { fit: 'cover', position: 'centre' })`
→ raw/PNG buffer. Then one `sharp({ create: canvas }).composite([...]).webp({ quality: 72 })`.

- Decode each distinct picture once per collage even when it fills several
  tiles (cache the input buffer by `fileId` for the call).
- Limit parallel tile work to 4.
- **A tile whose bytes cannot be read or decoded** takes the next picture in
  the deck, cover-cropped into the same rectangle. If fewer than
  `MIN_COLLAGE_POOL` pictures turn out readable, the request is a 404.
- Never throw raw sharp errors to the client; log and 404.
- No stored file is touched and nothing is written to disk or the database.
  The collage is not a `files` row, never appears in a gallery, export or
  backup.

`sharp` is already a dependency and already handled in the standalone and
Docker builds; no new native module.

## 5. Eligibility (`eligibility.ts`)

`filterForCollage(files, settings, repos)` is the **only** place a picture is
judged fit for a collage. With `settings.allowUncensored` true it returns the
input. Otherwise, per picture:

1. **Uncensored by bytes → out.** Ask `findUncensoredImages`
   (`lib/photos/uncensored-images.ts`) for the whole pool's sha256s in one
   call; any picture whose bytes carry an uncensored record is excluded, as
   the galleries' badge rule already works.
2. **`generationModeration === 'moderated'` → in.**
3. **`null` (unknown) → the guess.** Collect the chats named in `linkedTo`
   (one batched read for the whole pool, raw rows). The picture is out if any
   such chat
   - is Unmoderated now — `getConciergeState(chat) === 'unmoderated'`
     (`lib/services/dangerous-content/chat-override.ts`), or
   - has `isDangerousChat === true`.

   Otherwise — including a picture linked to no surviving chat — it is in.

**Deliberate exception to a standing rule.** CLAUDE.md says `isDangerousChat`
is classifier telemetry that no routing or display decision reads. This filter
reads it, in this one function, because it is the only evidence left about
pictures made before the moderation column existed. Keep the read inside
`eligibility.ts`, comment it as the exception, add a grep-test that no other
file under `lib/dynamic-backgrounds/`, `app/` or `components/` reads
`isDangerousChat` for this feature. The Concierge paragraph in CLAUDE.md
already names the exception (added with this spec, confirmed by the operator
2026-11-17); update its spec link when this file moves to `complete/`. The guess applies to `null` rows only; a
recorded value always outranks it.

The guess is fallible in both directions and the help page must say so.

## 6. Client

### 6.1 Hook

`hooks/useDynamicBackground.ts`:

```ts
useDynamicBackground(scope: 'home'): string | null
useDynamicBackground(scope: 'project' | 'character', id: string): string | null
```

- Reads `dynamicBackgrounds` from the existing chat-settings query (narrow
  with `select`; no second `queryFn` for that endpoint). Disabled → no
  request, returns null.
- `useQuery` on a new key block in `lib/query/keys.ts`:
  `queryKeys.dynamicBackgrounds.status(scope, id, orientation)`, fetched with
  `apiFetch`, signal forwarded.
- `refetchInterval: refreshMinutes * 60_000`,
  `refetchIntervalInBackground: false`, `staleTime` equal to the interval,
  `refetchOnWindowFocus: false` (focus must not reshuffle).
- **This interval is a rotation timer, not a poll for server changes**, so the
  "a new polling site is a bug" rule does not apply and no realtime topic is
  added. Say so in a comment at the call site.
- **Only the visible tab rotates.** Workspace tabs are kept alive; a hidden
  tab must not compose collages nobody sees. Gate `enabled` on the tab being
  its pane's active tab (use `useWorkspaceTabId` + `useWorkspace`; outside
  the workspace the gate is true).
- Orientation: `window.innerWidth >= window.innerHeight ? 'landscape' :
  'portrait'`, read when the hook mounts and on a debounced resize that
  crosses the boundary.
- **Preload before swapping.** When a new `url` arrives, load it with
  `new Image()` and only then return it; keep returning the previous URL
  meanwhile, and keep it if the load fails. This is what prevents a blank
  frame every refresh. No crossfade in this version.
- A changed setting takes effect when the chat-settings query updates: turning
  the feature off returns null at once; the uncensored toggle and the interval
  are part of the status query's key (or invalidate it in the mutation's
  `onSuccess`) so the next collage is drawn under the new rule immediately.

### 6.2 Wiring the three pages

In every case the dynamic URL takes the first place in the expression that
already chooses the background, and the existing value stays as the fallback.
Report to the workspace backdrop exactly once per view (see the workspace
keep-alive note about double-reporting).

- **Project** — `app/prospero/[id]/ProjectDetailView.tsx`:
  `const bg = dynamicUrl || storyBackgroundUrl`; use `bg` in the
  `--story-background-url` style and in
  `useReportWorkspaceBackdrop(bg || prosperoBackgroundImage || null, false)`.
- **Character** — `app/aurora/[id]/CharacterPage.tsx`: set
  `--story-background-url` on the `qt-page-container` root when `dynamicUrl`
  is set and report it with `useReportWorkspaceBackdrop(dynamicUrl, false)`.
  Check what the page shows today with no report and make sure a null URL
  leaves that unchanged.
- **Home** — `components/homepage/HomeViewContainer.tsx` (the workspace home
  tab; `/` redirects to it): `useReportWorkspaceBackdrop(dynamicUrl, false)`.
  The home view has no `::before` layer of its own and needs none, since the
  workspace backdrop paints it. Confirm text stays legible over the collage at
  the backdrop's existing opacity; if a panel needs a surface, use an existing
  `qt-*` class rather than a new one.

`isSalon` is always `false`: a Salon with a background still wins the
workspace arbitration, as today.

The collage is decorative: it stays in the `aria-hidden` backdrop / `::before`
layer and gets no alt text. Text contrast over it is held by the existing
layer opacity; check light and dark in at least the default theme and one
bundled theme.

## 10. Out of scope

- Collages on any other page (Salon list, Aurora list, Settings, groups).
- Crossfade or per-tile animation.
- A per-project or per-character opt-out, pinning or excluding pictures.
- Backfilling `generationModeration` on old rows.
- Persisting collages, or showing which pictures a collage used.
