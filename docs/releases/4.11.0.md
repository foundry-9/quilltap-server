*4.10 gave you the stage manager's book. You could pass a note from the wings, set a clock running on a character, have the Host build the set before the curtain rose, and the running order was drawn once and kept. What 4.10 could not do was put anything in the actors' hands, or let you stop the scene once it had started. A character could wear a coat but not carry a lantern. A room of five talked in rotation whether or not anyone had something to say. Once a reply began, the only way to end it was to pause the whole room and wait.*

*4.11 is the release in which the cast gets its props, and you get the floor.*

---

Where 4.10 let you direct the play, 4.11 lets you run the table it is played on.

**The Inventory** is the first. A character can now carry things: a lantern, a lockpick set, a sword with a name. Objects live on the same four shelves as the wardrobe (her vault, a group's store, a project's store, Quilltap General), as archetypes, instances and kits. She hears what she is carrying every turn, every portrait and backdrop shows it, and nine tools let her take things up, set them down, hand them on and make new ones. Pascal can read all of it.

**Storyteller mode** is the second. It is a third way to run a multi-character room, beside rotation and pause. When you speak, every character privately says whether they want to answer and what they mean to do. You see the bids on a board, tick the ones you like, put them in the order you want, and only those characters speak. To make that safe, **every tool now declares its effect** (`none`, `read`, `write` or `destroy`), so a character who only bid to look something up cannot rearrange the furniture on her turn.

**Interruption** comes with it. The composer now has three buttons: **Send**, an amber **raised hand** that asks whoever is speaking to yield, and a red **Stop** that ends the reply where it stands and keeps what was said.

**Pascal the Croupier** had the busiest cycle of anyone. His tools can run when someone says a **trigger phrase**, **dress and undress** the character who rolled, test and change what she **carries**, combine their gates with **OR**, write to a new shared **Log**, speak **as the character** instead of as Pascal, and be **held for you** before they land, so you can change the roll, the answer or the verdict, or veto it. A character can now write and fix her own tools with `edit_custom_tool`. The composer's new **slash commands** put all of them one `/` away.

Smaller pieces round out the release. The wardrobe keeps an **outfit history** per chat, with a *Wear again* button and a tool that lets a character change back. Items can carry **pronoun guidance**. The Commonplace Book gains **keystone** memories you mark as always remembered, reserves room in recall for **the people closest to a character**, and has a recalibrated **importance scale**, so "agreed to build the parser" no longer sits beside "is expecting a child." The **Novel** roleplay template writes narration as plain prose and dialogue in quotation marks. The **Brahma Console** floats over every page. The **LLM Inspector** now logs every call the Salon makes, including the ones that failed.

Three changes are worth reading before you upgrade, and all three are under **Upgrading**: custom tools in a character's vault are now **that character's only**; characters may **manage their own inventory by default**; and in an autonomous room, two more tools (`doc_delete_blob` and `delete_annotation`) are now **gated as destructive**.

The thesis is simple: *4.10 let you direct the play. 4.11 hands the actors their props, and lets you say "stop."*

## Props: The Inventory

### Things a Character Carries

A wardrobe answers *what is she wearing*. Nothing answered *what is she holding*. The **Inventory** does. Every object is one JSON file in an `Inventory/` folder on one of the four tiers the wardrobe already uses, and a character reaches them in the same order: her own vault, then her groups, then the project, then Quilltap General.

There are three kinds of object:

- An **archetype** is a pattern, such as *longsword* or *brass lantern*. Nobody carries an archetype.
- An **instance** is a real object made from one. It stores only what it changes (a title, a description, a few `metadata` values) and inherits the rest. *Excalibur* is an instance of *longsword*. Change the archetype's picture and every plain sword in the house follows. **Detach** an instance to fix its values in place.
- A **kit** is a named set, such as *burglar's kit*. Equipping a kit equips its members, making instances in the character's vault for any members that are archetypes.

Each object has **two descriptions**: one for the model ("a sword with a chipped edge and a history") and one for the painter ("a longsword with a jewelled pommel"). It can also have a picture, an SVG or emoji glyph, `metadata`, a cap on how many of its kind one character may carry at once, and an *equipped by default* flag, so a character arrives in a chat already holding it.

### What She Knows, and What the Painter Sees

What a character carries reaches her as a short **Carried and equipped** section at the end of every turn's context, after progressions and before informs. It is on the opening greeting too, and on Carina's answers. When nothing she carries has a description, the section is left out entirely, so the turn is byte-identical to one in 4.10.

The painter's descriptions become one phrase, *carrying a longsword with a jewelled pommel, …*, which reaches avatars, story backgrounds and the image tool. Avatars are cached by their prompt, so picking up a new sword gets her a new portrait, and setting it down brings the old one back. An object with no painter's description stays out of every picture.

### Nine Tools, and a Croupier Who Can Count

A new character flag, **Can manage inventory** (next to Self-Dressing in Aurora), gives a character nine tools: `inventory_list`, `inventory_read`, `inventory_equip`, `inventory_unequip`, `inventory_pick_up`, `inventory_create`, `inventory_update`, `inventory_archive` and `inventory_give`. She can take an archetype off a shared shelf (which makes her an instance), hand her own things to another character, or make something new. Each character's changes in a turn are summed into one line from Pascal at the end of it, such as *Bertie takes up some lockpicks and sets down the lantern*. A give gets its own line.

Pascal reads the Inventory too. A custom tool can be gated on what a character carries, or on how many of something she has. An outcome can quote `{{inventory.excalibur.title}}`, a roll can use an object's `metadata` as its number, and an effect can equip, unequip or pick something up. Every reference, from a tool, a placeholder or an effect, is resolved by one rule: id, then title, then name, case-insensitive.

That rule makes titles risky. If an object were titled *sword*, it would silently take the place of every gate and placeholder that means the archetype *sword*. So every Inventory write, through the editor, a tool, the Scriptorium or a `doc_*` call, is checked first. A title that would shadow an object's name or a live custom-tool gate is **refused**, with a message naming the collision. If the check cannot read what it needs, it refuses rather than guessing.

### Where to Find It

The left rail has an **Inventory** button with its own open-box icon. It opens a tab in the workspace, or a dialog scoped to the chat when you are in the Salon. Each participant card has an Inventory button beside the wardrobe's, and each project has an Inventory card in Prospero. The dialog has a **Carrying now** pane for each cast member, with *Take up…* and *Reset to defaults*.

The **project roster** gates the project's shelf the way it already gates the project wardrobe: a character the roster does not admit cannot take from the shelf, though anything she already carries stays in her hands. Backups, restores and `.qtap` exports carry all of it, and a new-account restore re-keys each chat's carried set to the new character ids.

## Who Speaks Next

### Storyteller Mode

A busy room has always worked by rotation: everyone has a turn, whether or not they have anything to say. **Storyteller mode** is a third setting on the sidebar's turn control, beside **Normal** and **Paused**, for when you want to run the table yourself.

In a storyteller chat, your post does not draw a reply. It opens a **round**. Every character present is asked, at the same time and in private, whether they want to answer and what they mean to do. Each bid is a full in-character call built the way an ordinary turn is built, with her tools visible but unusable, and **nothing it writes is kept** except the log. The bids appear on a **board** above the composer as they arrive, each marked with a tier: **Simple** (just speaking), **Lookup** (reading something), **Act** (changing something) or **Destroy**. If the tools a character named would do more than she claimed, the board raises the tier and says so.

You tick the bids you like and drag them into the order you want. Then you choose to run them **in sequence** or **all at once**. All at once runs the Simple and Lookup turns side by side and the Act and Destroy turns after them, in order. Each chosen character speaks with her plan in front of her and her tools **capped at the tier she bid**. A character who bid to look something up cannot delete a file on her turn. She may still pass. **Ask anyway** asks a character who did not bid; **Let it lie** closes the round with no replies. Memory extraction, the summary, scene tracking and danger classification run once at the end of the round, not once per speaker.

An *Invite by talkativeness* toggle invites the quieter characters less often. A nudge still runs one turn, and a whisper or an `@Name:` query opens no round. Rounds are not exported or backed up; a chat's mode is.

### Every Tool Says What It Does

Storyteller mode needed something Quilltap did not have: a way to know what a tool will do before it runs. **Every tool now declares an effect**: `none`, `read`, `write` or `destroy`. Built-in tools declare theirs next to their definitions, and a test fails the build if one is missing. A few tools, such as `state`, `run_custom` and `doc_open_document`, work theirs out from the call. A custom tool is `write` if it has any effect and `read` otherwise, shown as a badge in the Workbench. Plugins can declare effects too, and an MCP server's tools inherit an effect set in its config (default `write`).

A turn can now carry an **effect ceiling**. Tools above it are left out of the request, and a call above it is refused with a reason. Storyteller turns use this, and so does the autonomous-room gate, which replaces its hand-kept list of destructive tool names with a `write` ceiling (see **Upgrading**).

### Raise a Hand, or Stop

The composer now has **three buttons** in a column beside the editor: **Send**; an amber **raised hand**; and a red **Stop**. The last two light up only while someone is speaking.

**Stop** ends the reply where it stands. Whatever had been written is saved as an ordinary message, with any tool results it had already produced, and no further tool call runs. There is no fallback, no failover, no recovery attempt and no answer-confirmation pass. A stop before any prose saves nothing. In a multi-character room, Stop pauses the room first, as the old sidebar button did. (That button is gone; Stop lives in the composer now.)

**Raising your hand** is gentler. The next turn to be built is told that you would like the floor and may answer `[YIELD]`. If she yields, the Host says so and the floor is yours, without advancing the rotation. If she carries on, the Salon tells you she declined.

### A Whisper Is One Reply

A whisper from the Whisper dialog used to start a whole turn chain of its own, in a stream the Salon never displayed, alongside any chain already running. Now it gets **one reply** from the character you whispered to, waits for any stream already in progress to finish first, and then hands the floor back to you (bug 258).

## Pascal Learns the Room

### Trigger Phrases

A custom tool can now list up to eight **trigger phrases**. With *Auto-Run Custom Tools on Trigger Phrases* switched on (Settings → Chat → Automation, **off** by default), every saved message, yours or a character's, is scanned. Each tool whose phrase appears runs once, with default parameters, from the speaker's point of view. A *private* tool whispers its result to the speaker. Swipes trigger nothing, and no more than four tools run per message. The Workbench warns you when a tool's own message quotes one of its triggers, since that would set it off again.

### Dressing by the Dice

A custom tool's effect can now be a **wardrobe gesture** instead of a value: *wear*, *take off* or *clear a slot*, applied to the character who rolled. Item references are templates, so `{{outcome.state}}` can choose the coat. Changes from the tool and the character's own wardrobe calls in the same turn produce **one** Aurora announcement. The Workbench gives each side-effect row a **Choose…** picker that browses outfits and garments by slot, with thumbnails, the tier each item is found on, and a note when a chosen item does not cover the slot you named.

Taking off a composite outfit now takes off its pieces. Before, `wardrobe_take_off` on a worn outfit removed nothing, because a worn outfit is stored as its pieces.

### The Character Says It

A new `{{character}}` placeholder gives the rolling character's name in messages, chip labels, consult prompts, effects and wardrobe references. A tool marked **The character announces it** posts its result under the character's own name and avatar instead of Pascal's. The roll record stays Pascal's, so it still cannot be fudged.

### Broader Gates

A tool's availability gates, and the `when` tests on outcomes and effects, could only require that *all* conditions held. They now accept **OR**: a list of AND-groups, any one of which may hold (one level deep, at most eight). The Workbench shows an AND/OR toggle between chips.

A new **`inventoryAggregate`** subject looks across everything a character carries, owns or can reach, by count, names, titles or a `metadata` field, with `min`, `max`, `sum` and `count`. For example, *available when the total `weight` she is carrying is under 40*. Comparing a list now checks each entry, which also makes a character-sheet `metadata` key that holds a list match correctly. Before, it never matched.

### When the Table Has Already Decided

A tool that rolls, then asks a model to narrate, used to ask the model to compare the numbers itself, and models sometimes got the comparison wrong (bug 257). An outcome row can now carry a **brief**: the conclusion it stands for. When the table does not depend on the model's answer, the outcome is decided first and the prompt quotes `{{outcome.brief}}`, so the model is told the verdict instead of asked to work it out. The Workbench warns when a prompt compares numbers, and when a row it reads has no brief.

### Taking a Hand in the Roll

A custom tool can now be marked **intervenable**, with a switch for each field you are allowed to change. When a character's `run_custom` call or a trigger phrase runs such a tool, it is **held** after the deal and before anything is applied or posted. A dialog opens in the Salon, survives a reload, and appears in a second tab. It shows the roll, its range (the minimum and maximum it could have been under these parameters), the value, the consult's prompt and answer, the outcome, and every effect.

You may change any field you allowed and watch the rest recompute **without a reroll**. You may re-ask the model, run it as rolled, or **veto** it. A veto posts nothing and applies nothing. A plain character is told only that *the tool did not run*; a character with system transparency, or a seat you are playing, is told *the table is closed*. The model is never told that a hand was on the table. A changed deal is recorded in the roll's metadata and shows a hand badge on Pascal's chip, but no model ever reads it.

Holds happen only in the main process, never in autonomous rooms, and only with *Let me take a hand* switched on in Settings → Chat → Automation (on by default; a tool must also be marked intervenable before anything is held).

### The Log

**The Log** is a shared notebook in the LLM logs database, for things a character wants to write down and find again. `log_create_entry` stamps a line with the chat and the character, `log_grep` searches every entry with a regular expression, and `log_read` filters by chat, character and date. A bare date includes the whole day. Custom tools gain a fourth effect, `{ "log": "<template>" }`, to write a line when they run. Entries are pruned under the LLM log retention period, even with LLM logging off, and are not included in exports or backups. Brahma and `quilltap db` both know the new table.

### A Tool That Edits Tools

`edit_custom_tool` lets a character **save or validate** a custom-tool definition in a store's `Tools/` folder. It checks the definition against the same schema discovery uses and refuses a name already taken in that store. It writes through the ordinary document path, so store access, the Librarian's announcement and the reindex all apply. Called with `action: "schema"`, it returns the published JSON Schema and two worked specimens, so a model can write a tool from nothing. It is offered whenever custom tools are on. Tool settings have a new **Pascal's Custom Tools** category, and `run_custom` has moved into it.

## The Wardrobe Remembers

### Outfit History

Every chat now keeps a numbered **outfit history** for each character, starting at entry 0 with what she arrived in. One entry is added per Aurora announcement, so a tool call, a closed dialog, a Pascal roll or a whole turn of changes each adds one, along with **who did the dressing**: *the operator, as Bertie*, *Jeeves*, or *Pascal's dress_for_dinner (rolled by Jeeves)*.

The Wardrobe dialog has a **History** tab, newest first, with **Wear again** on every entry. Two new tools, `wardrobe_history` and `wardrobe_rollback`, let a character look back and change back herself. A rollback moves a cursor instead of adding an entry, so going back and forward does not renumber anything. Garments archived or deleted since are left off, and the result says which. The history travels in exports and backups, and existing chats start with their current outfit as entry 0.

### Pronoun Guidance

A wardrobe item can name the pronoun sets it is meant for. A character whose pronouns are not on the list is not offered it: `wardrobe_list` holds it back (and says how many it held back), the *Let character choose* pass skips it, and the pickers hide it behind a **Pronoun-aware** checkbox that is on by default. An item with no guidance is offered to everyone, as is a character with unset or custom pronouns. Guidance never stops anyone from wearing an item asked for by id or title.

### Smaller Fittings

- **Copy to folder…** files a copy of an item, with its pictures, anywhere in its wardrobe. Moving or copying an outfit now asks what to do with its pieces, as moving it to another wardrobe already did.
- A character's gallery has a third section, **Wardrobe Pictures**, holding every generated picture of every garment she can wear, captioned with where it hangs.
- A styled hair slot is now described as overriding the natural hair in the physical description. Before, a portrait's prompt could say "perfectly straight hair" next to "voluminous emerald curls" without saying which applied.
- The wardrobe and inventory tools now ask the model for a short **visual cue** with every new garment or object. The painter never reads the description, so without a cue an avatar or backdrop got only the item's title. The text-block form of `CREATE_WARDROBE_ITEM` had also been dropping its description silently; it no longer does.

## The Commonplace Book Knows Who Is Family

### Keystones

Some facts should never fade: a marriage, a death, the name of a child. You can now mark a memory as a **keystone** ("Keystone — always remembered" in the memory editor, or `quilltap memories keystone <id> --write`). Keystones are recalled in full text, ahead of digests, every turn they are relevant. Maintenance never folds, consolidates, demotes or retires one, and a chat wipe spares them. Each character may hold up to five per subject, and archived memories cannot be marked. The list has a *Keystones only* filter, and the CLI marks them with ◆.

### Those Closest to You

Recall's standing archive now reserves room for **the people closest to a character**: everyone she shares a group with, ranked by how small the group is. Three digests go to members of her tightest group, two to the next, one to the rest. They appear in full text under a new **Those Closest to You** heading, capped at a third of the archive. A character's sister is no longer pushed out of mind by a fortnight of meetings. The section is rebuilt from current group membership every turn, so a change to the group takes effect on the next turn.

### Rating a Promise

The extraction prompts' importance scale put every spoken commitment at 0.90, so *agreed to build the importer* sat next to pregnancies. Because ties go to the newest, a long build session could fill the archive's importance slots. The scale is recalibrated across all four prompts. 0.95 is for facts that redefine a life or a bond: marriage, vows, pregnancy, birth, death, a change of body, someone joining or leaving the family. 0.85 is for revelations and personal promises about a relationship. Work commitments are capped at 0.65, and passing work decisions sit at 0.45. A family fact now scores 0.95 however it comes up, even when it is mentioned over breakfast. Existing memories are not rescored.

## The Composer

### Slash Commands

Type `/` at the start of a word in the Salon composer to open a command menu: composer actions (`/attach`, `/image`, `/inform`, `/mail`, `/roll`, `/d20`, `/coin`, `/bottle` and more), every built-in tool you can use, and every Pascal tool in the chat, by name. A command with nothing to fill in runs at once. One with parameters opens its usual dialog with the tool already chosen. The menu ignores `and/or`, `10/15`, URLs, paths and code. It can be switched off under Settings → Chat → Slash Commands.

### The Novel Template

A new built-in roleplay template, **Novel**, writes the way a printed novel does. Narration is unmarked prose, shown in italics. Dialogue goes in quotation marks, straight or curly, and can run across several paragraphs without a closing quote. `*Emphasis*` is shown bold and italic, and `((OOC))` uses the out-of-character style. The features that make this possible are available to every template in the editor: unmarked narration, a style for unclaimed text, curly-quote matching, optional closing delimiters, and treating `*` as a delimiter instead of Markdown.

Fixing this turned up an older bug. A narration pair such as Quilltap RP's `[` … `]` had been stored as text and read back as a single string, and a `null` read back as `*`. Both now read back correctly.

### Lexical 0.52

The composer's editor moved from Lexical 0.43 to 0.52. Two bugs were fixed along the way: Enter on a code block's blank last line now leaves the block instead of sending the message (bug 251), and an undo followed by clearing the composer can no longer leave a typeahead menu stuck at the top-left of the window (bug 250, a race new in 0.52).

## Elsewhere in the House

### Brahma, Always to Hand

The **Brahma Console** now has a launcher in the bottom-left corner of every page, and its floating window sits **above every dialog** without closing them. You can ask Brahma something halfway through editing a character. It stays mounted while hidden, so a reply keeps streaming and reopening it returns to the same conversation. The workspace tab and the floating window each keep their own current conversation. The header gains a model picker and *Past conversations*.

### The Inspector Sees Everything

The LLM Inspector logged a Salon call only if it reached a clean finish, so a primary that refused or stalled never appeared beside the failover that replaced it. Every call is now logged however it ends: a call that failed with its error and partial text, an abandoned one with a note. Swipe regeneration, request-limit recovery, image description, cheap-LLM failures, the opening greeting and manual image generation, all previously missing or unlinked from their chat, are now logged. Storyteller bids have a filter and round chips of their own.

### Ariel Reads the Screen

`terminal_read` and Ariel's summaries used to strip escape codes from terminal output, which reduced full-screen programs like vim, `less` and Claude Code to fragments: 422 KB of output read back as 526 characters. Output is now rendered through a real terminal emulator, so a character sees what is on the screen (bug 255). A closed session is replayed at the size it ran at.

### Smaller Courtesies

- **My Photos** (`/photos`) no longer lists character vaults, so a promoted avatar roll does not appear twice. An **album selector** opens any single store's album instead.
- **Image prompts are cleaned only when it matters**: in a Moderated chat whose image is going to a moderated painter. An uncensored image profile is never cleaned or rerouted, and an Unmoderated chat sent to a moderated painter is left to the refusal failover.
- **Published vault addresses name the vault.** `qtap://self/…` means *the reader's* vault, and Quilltap had been handing such addresses to every character in a chat. A request for Abigail's `metadata.json` could open Friday's, with no error (bug 256).
- **Scenario lists sort by title**, ignoring a leading *The*.
- **Toasts** raised from inside a dialog now appear above it instead of behind it.

That fixed bug 252: a new-account restore had left every restored chat's characters wearing nothing.

## Repairs

Bugs 247 through 258 were filed and closed in the cycle. The larger ones are covered above. The rest:

A `when` phrase naming "constructor" as its month threw on a JavaScript prototype key and failed the whole memory extraction job. Now it costs that one draft its date (bug 247). The conversation renderer decided which chunks to embed by re-reading them after a buffered write it could not yet see, so new and changed chunks went unembedded (bug 248). A chat with one character and no persona made the character answer about twenty times in a row, until the chain hit its depth cap (bug 249). The carried-objects section and the progressions report were both skipped on every turn that did not answer a new user message, which covers every chained speaker, every nudge and every autonomous room (bugs 253 and 254). The Inventory's own review fixed a give that unequipped the giver before the transfer had succeeded, an archived object that a restore would have re-equipped, and Pascal's line announcing changes before the reply it summarised.

## Upgrading

**Fourteen migrations run on first boot**, all quick. They add the carried-object column and the *Can manage inventory* flag; the outfit-history table, its tool-name column and a seed entry 0 for each chat's current outfit; storyteller mode and its LLM-log round column; the keystone column; the roleplay-template fields for unmarked narration; the terminal session size; and the chat settings for slash commands, trigger phrases and intervention.

**Custom tools in a character's vault are now hers alone.** Until now, every co-participant's vault tools were dealt to every character in the chat, and a `disabled` definition in one vault hid that tool from everyone in the room. Now a vault's `Tools/` folder serves only its owner. The tiers are character, group, project, then global. If the cast relied on one character's tool, move it to a group, project or Quilltap General. You can still run any vault tool from the Salon popup, as its owner.

**Characters may manage their own inventory by default.** *Can manage inventory* starts **on** (an unset flag reads as on), the same as Self-Dressing. Turn it off in Aurora for any character who should not be taking things off shelves.

**Two more tools are gated as destructive in autonomous rooms.** The hand-kept list of destructive tools is replaced by declared effects. `doc_delete_blob` and `delete_annotation` are now `destroy`, so a room without *destructive tools permitted* no longer offers them. Every tool from a plugin that declares nothing, including each MCP server's, counts as `write`.

**Stop has moved to the composer.** The participant card's Stop button is gone. The red octagon beside Send does the same job, and more.

**Image prompts are cleaned less often.** An Unmoderated chat sending images to a moderated provider is no longer pre-cleaned; a refusal is caught by the Concierge's failover instead. An image profile marked uncensored is never cleaned or rerouted.

**My Photos no longer shows character vaults.** Those pictures are under each character's album in the new selector, and in Aurora as before.

**New chat settings and their defaults:** slash commands **on**; trigger phrases **off**; *Let me take a hand* **on* (nothing is held unless a tool is also marked intervenable). `run_custom` has moved to the *Pascal's Custom Tools* category in tool settings. Existing per-chat tool choices are unaffected.

**Existing memories are not rescored.** The new importance scale applies to memories written from now on. Mark the facts that matter most as keystones.

**An export that holds a trigger-phrase roll will not validate on 4.10.** It imports fine on 4.11. On an older build, that one message's roll record fails validation.

**The Log and storyteller rounds are not exported or backed up.** The Log is pruned with your LLM log retention period. A chat's turn mode and each storyteller reply's bid do travel.

**Provider prompt caches are not rolled.** No prompt-builder version changed. The carried-objects section rides in the uncached tail, and a turn with nothing carried, no keystones and no group circle produces the same bytes it did in 4.10.

Node.js 24+ is still required, unchanged from 4.10.

## Installation

### Electron Desktop App

Download the latest `.dmg` (macOS), `.exe` (Windows), or `.AppImage` (Linux) from the [quilltap-shell releases page](https://github.com/foundry-9/quilltap-shell/releases/latest). The window is only ever a front end, and it offers three back ends: **Direct** (the Node server inside Electron, no isolation), **Docker** (the container image behind a native window, which is the recommended setup and the strongest boundary we ship), and **Remote** (any Quilltap URL, including a dev server, an `npx quilltap` instance, or a machine on your network). Requires shell 4.2.0 or later.

### npm (Node 24 required)

```bash
npm install -g quilltap
quilltap
```

Open `http://localhost:3000` in your browser. Requires Node.js 24+. First run downloads and caches locally.

### Docker

```bash
docker pull foundry9/quilltap:4.11.0
```

Or use the startup scripts:

```bash
# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/foundry-9/quilltap-server/refs/heads/main/scripts/start-quilltap.sh | bash

# Windows (PowerShell)
irm https://raw.githubusercontent.com/foundry-9/quilltap-server/refs/heads/main/scripts/start-quilltap.ps1 | iex
```

### Standalone Tarball

Available for environments where npm global installs and Docker are both impractical. See the GitHub releases page for download links.
